# Replace SonarQube with free point tools

Researched 2026-10-24 from the notes in `docs/research/research_notes/CI security tooling for solo dev/`. Prices are as of October 2026. Several came through aggregators or summarising fetches, and those are flagged inline.

A solo developer on GitHub Free doesn't need a paid security platform to do better than SonarQube. Free SonarQube has no data-flow (taint) analysis, so it finds little real security signal. A few free point tools, each answering one question, beat it, and forge-lab already runs most of them: gitleaks, zizmor, actionlint, `bun audit`, and Dependabot with a 7-day cooldown, all in a no-secrets, SHA-pinned CI. What's missing is a real SAST engine, malicious-package detection on dependency bumps, and security testing for the thing this project actually is, an LLM agent harness. The best fixes are **Semgrep Free Edition** for SAST plus supply-chain reachability (it now parses text `bun.lock`), **Socket's free GitHub App** for malicious packages, **promptfoo's agent red-team** against the loopback harness, and Claude Code's **`/security-review`** run locally. All four are $0 apart from LLM tokens. GitHub Free blocks the platform route anyway: a personal account can't buy GitHub Code Security or Secret Protection, so there's no Security tab, no SARIF UI and no server-side secret scanning on private repos. Paid AI reviewers, AI pentest services and commercial DAST cost $30 to $4,000+ and add little for a loopback-only learning project. The one paid upgrade worth having is a capped monthly LLM budget, not a subscription. WorkOS sells no code-security product at all.

## Free SonarQube finds style, not vulnerabilities

The reason to drop SonarQube is in Sonar's own documentation. Security Hotspot rules "aim to guide security auditors during code review rather than pinpoint real vulnerabilities", and hotspots don't count toward the Quality Gate ([Sonar docs](https://docs.sonarsource.com/sonarqube/latest/user-guide/rules/security-related-rules)). **Taint tracking, the analysis that follows untrusted data across functions and files to find injection bugs, is a commercial feature** missing from the free Community Build ([SonarSource](https://www.sonarsource.com/products/sonarqube/why-upgrade/community-build/)). Sonar keeps moving depth into paid tiers. The 2025.4 release made "Advanced Security" (SCA plus a new JS/TS taint engine) a paid add-on ([Sonar blog](https://www.sonarsource.com/blog/sonarqube-server-2025-4-faster-analysis-stronger-security-better-coverage/)). SonarQube Cloud's free plan covers private projects up to 50k LOC, but Team starts at **$34/month** and the page is unclear about which plan includes SCA ([Sonar pricing](https://www.sonarsource.com/plans-and-pricing/)). In this repo, Biome and `tsc` already cover the code-quality half, so SonarQube would add overlap without security depth.

The independent guidance points the same way. The OpenSSF Concise Guide recommends several detection tools in CI, but "not as the only safeguard". Its list leads with MFA, protected review, dependency monitoring, a ~3-day cooldown on non-security updates, and never pushing secrets ([OpenSSF](https://best.openssf.org/Concise-Guide-for-Developing-More-Secure-Software)). Latio's 2026 market report says false-positive reduction and developer experience now matter more than raw finding volume ([Latio via Datadog](https://www.datadoghq.com/ja/resources/latio-application-security-report2026/)). Both argue for fewer, quieter tools. For one person, the likeliest compromise path is a stolen token or a poisoned CI dependency, not an injection bug a scanner would find. The tj-actions chain started with a compromised PAT ([Wiz](https://www.wiz.io/fr-fr/blog/github-action-tj-actions-changed-files-supply-chain-attack-cve-2025-30066)), and Trail of Bits traces the 2026 Trivy compromise to a `pull_request_target` misconfiguration ([Trail of Bits](https://blog.trailofbits.com/2026/05/22/we-hardened-zizmors-github-actions-static-analyzer/)). forge-lab's existing controls (no secrets in CI, `permissions: {}`, SHA pins, `persist-credentials: false`, Lefthook gates) already cover the riskiest ground. Scanners come after those.

## GitHub Free shuts the platform door, so feedback lives in CI logs

One constraint shapes every choice below. **SARIF upload to code scanning fails on private repos without GitHub Code Security** ("GitHub Code Security or GitHub Advanced Security must be enabled") ([GitHub Docs](https://docs.github.com/en/code-security/code-scanning/integrating-with-code-scanning/uploading-a-sarif-file-to-github)). **Only GitHub Team or Enterprise plans can buy Code Security or Secret Protection** ([GitHub Docs](https://docs.github.com/en/get-started/learning-about-github/about-github-advanced-security)). The only way in is to move the repos into an organisation on Team ($4/user, per [github.com/pricing](https://github.com/pricing)) and add Code Security at $30 and/or Secret Protection at $19 per active committer. That's roughly **$34–53/month**, and those figures come from 2025 changelogs ([GitHub changelog](https://github.blog/changelog/2025-03-04-introducing-github-secret-protection-and-github-code-security/)). The same paywall covers Copilot Autofix on private repos ([GitHub security plans](https://github.com/security/plans)) and Scorecard's action ([Scorecard action](https://github.com/marketplace/actions/ossf-scorecard-action)). StepSecurity Harden-Runner, the tool that first caught tj-actions, says flatly that its free Community tier "does not support private repositories" ([StepSecurity docs](https://docs.stepsecurity.io/getting-started/quickstart-community-tier)).

So every tool has to report through exit codes, `--format=github` annotations, CI logs, or its own vendor dashboard. Branch protection isn't enforced on Free private repos ([SSW](https://www.ssw.com.au/rules/which-github-plan)), so a red run is advice, not a block, which `ci.yml` already says. That favours tools that fit the existing `fetch-binary` pattern and fail a job, over tools whose value lives in a GitHub Security tab you can't see. It also argues against stacking GitHub Apps. Each app is a standing credential holder, and the CodeRabbit RCE showed that a leaked app private key can mean write access to about a million repos at once ([Kudelski Security](https://kudelskisecurity.com/research/how-we-exploited-coderabbit-from-a-simple-pr-to-rce-and-write-access-on-1m-repositories)).

## Semgrep Free fills the SAST gap, and Socket covers what CVE feeds miss

### Static analysis: Semgrep Free beats Aikido, Snyk and the AI-native vendors on fit

Two free tiers cover a solo dev's private repos in one product. **Semgrep Free Edition** includes Code and Supply Chain for up to 10 contributors and 10 private repos, *with* cross-file analysis, reachability and 60 AI credits ([Semgrep pricing](https://semgrep.dev/pricing)). Cross-file analysis and reachability are exactly the depth free SonarQube lacks. TypeScript is GA with cross-file dataflow ([Semgrep docs](https://docs.semgrep.dev/supported-languages)). **Semgrep v1.179.0 (2026-10-01) added parsing for text `bun.lock`**, though the official feature docs don't list Bun yet and the release is three weeks old ([newreleases.io](https://newreleases.io/project/pypi/semgrep/release/1.179.0)). **Aikido Developer** (2 users, 10 repos, SAST, SCA with reachability, secrets, IaC, and `bun.lock` officially listed) is the other choice ([Aikido pricing](https://www.aikido.dev/pricing); [Aikido help](https://help.aikido.dev/code-scanning/scanning-practices/support-for-dependency-scanning-by-language)). But Aikido runs as a GitHub App that scans on its side, and its PR security review is a Basic feature at about 300/month for 10 users. On Free, findings stay in its dashboard.

Semgrep wins for this repo because it runs as a CLI inside the CI that already exists, and it can fail a job. The cost is a `SEMGREP_APP_TOKEN` in one job, which breaks the "no secrets in CI" rule for that one job and should be recorded in `docs/research/security-review.md`. Semgrep's privacy page returned a 404, so exactly what gets uploaded (findings metadata, possibly snippets) is unverified. If no account or token is acceptable, **Opengrep**, the LGPL fork of Semgrep CE, is the fallback: a pinned binary with no secret. Sources disagree on whether it restores cross-*file* or only cross-*function* taint ([AppSecSanta](https://appsecsanta.com/opengrep-vs-semgrep)), and it has no SCA.

The other options fail on a specific point. **Snyk Free** has no `bun.lock` support, since its JS docs list only npm, pnpm and Yarn ([Snyk docs](https://docs.snyk.io/supported-languages/supported-languages-list/javascript.md)), and it caps Code at 100 tests a month ([Snyk plans](https://snyk.io/plans/)). **DeepSource** has no free private-repo tier ([DeepSource](https://deepsource.com/pricing)). **Codacy's** free tier is IDE-only ([Codacy](https://www.codacy.com/pricing)). **Endor Labs** and **Checkmarx/Veracode** are sales-led ([Endor Labs](https://www.endorlabs.com/pricing)). Among AI-native SAST vendors, **Corgea Free** (2 users, 10 repos, 10 PR scans/month) is the only one claiming logic and auth analysis at $0 ([Corgea](https://corgea.com/pricing)). An independent tester measured about 50% false positives from it, though ([Joshua Rogers](https://joshua.hu/llm-engineer-review-sast-security-ai-tools-pentesters)). **ZeroPath**, that tester's top pick, starts at **$1,000/month plus $60/dev** ([ZeroPath](https://zeropath.com/pricing)). No vendor-neutral false-positive benchmark on TypeScript exists. The published OWASP Benchmark numbers are Java and come from a competitor's blog ([xygeni](https://xygeni.io/blog/top-sast-tools/)).

### Dependencies: known CVEs are covered, malicious packages aren't

`bun audit` plus Dependabot alerts already answer the known-CVE question. OSV-Scanner supports `bun.lock` too ([osv-scanner releases](https://github.com/google/osv-scanner/releases)), and Semgrep Supply Chain adds reachability, so a third CVE scanner would mostly repeat findings. OSV-Scanner is worth adding only if `bun audit`'s weak spots start to hurt: no per-version dedup and partial workspace paths ([OWASP case study](https://owasp.org/cve-lite-cli/docs/case-studies/cline)).

Malicious packages are the real gap, and the incident record shows why. Shai-Hulud, tj-actions and Trivy were caught first by behavioural detectors (Aikido, Socket, Harden-Runner), not CVE feeds, because advisories follow detection ([Phoenix Security](https://phoenix.security/tj-actions-compromise/); [Krebs mirror](https://tagteam.harvard.edu/hub_feeds/4281/feed_items/15925827/content)). forge-lab's `ignoreScripts = true` removes Shai-Hulud's install-time path. The 7-day cooldown in `dependabot.yml` and `bunfig.toml` covers the usual hours-long window before a malicious release is spotted. What's left is a bump that lands on a version compromised for longer than seven days. **Socket's free plan** covers that: 1 dev seat, 1,000 scans/month, **unlimited private repos**, and a GitHub App that warns or blocks on PRs ([Socket pricing](https://socket.dev/pricing)). Its comments would land on the weekly Dependabot PRs. Two caveats: nothing official confirms it parses text `bun.lock`, and scanning GitHub Actions needs Business. Treat Socket as a trial. Install it on forge-lab only, open a Dependabot PR, and remove it if it reports nothing about Bun dependencies.

### Secrets and Actions: already done, keep it pinned

The `secrets` job (gitleaks over full history, pinned by SHA-256) and the `workflows` job (actionlint and zizmor) are the right design. Running the gitleaks **CLI** instead of gitleaks-action avoids the action's EULA and its license call to Keygen ([gitleaks-action README](https://raw.githubusercontent.com/gitleaks/gitleaks-action/v2.3.9/README.md)). One thing is worth watching. In March 2026, gitleaks' creator launched **Betterleaks**, an MIT-licensed, config-compatible successor, saying he no longer fully controls the gitleaks repo ([BleepingComputer](https://bleepingcomputer.com/news/security/betterleaks-a-new-open-source-secrets-scanner-to-replace-gitleaks)). The swap only changes the `fetch-binary` URL and digest, so it's a cheap move once Betterleaks has a track record. Its recall benchmark (98.6% vs 70.4%) is self-reported. Poutine overlaps with zizmor ([poutine](https://github.com/boostsecurityio/poutine)), Scorecard on a Free private repo is CLI-only and mostly duplicates zizmor and the pins, and Harden-Runner isn't available free here. The Trivy compromise is the lesson behind the current design. Attackers rewrote 75 of 76 `trivy-action` tags and the payload stole CI secrets while the real scan ran normally ([Snyk](https://snyk.io/articles/trivy-github-actions-supply-chain-compromise/)). Scanners are supply chain too, so keep fetching them as digest-pinned binaries and never give them secrets.

## For an agent harness, red-teaming the agent beats DAST on the web layer

The dynamic side has to match the risk surface. forge-lab's server binds to loopback, runs only while you work, and has no deployed users. Its real risks are tool misuse, indirect prompt injection through tool outputs, and Approval bypass, not classic web bugs. Commercial DAST is out on price or scope. StackHawk retired its free tier and now starts at **$10/user/month** (aggregator figure) ([agentdeals](https://agentdeals.dev/vendor/stackhawk)). Burp Pro is **$499/year**, and Escape is quote-only and aimed at mid-market ([CodeAnt](https://codeant.ai/blogs/burp-suite-pricing); [Expert Insights](https://expertinsights.com/application-security/escape-in-depth-review-analysis)). ZAP's free API-scan action can target a server inside the runner ([zaproxy/action-baseline](https://github.com/zaproxy/action-baseline); [OneUptime](https://oneuptime.com/blog/post/2026-01-25-owasp-zap-api-security/markdown)), but it pays off only once there's an OpenAPI spec and a surface worth fuzzing. Nuclei mainly finds known CVEs in off-the-shelf software and had a template-signature bypass until 3.10.0 ([CVE-2026-76802](https://corgea.com/advisories/vulnerabilities/CVE-2026-76802)).

**promptfoo is the strongest fit and the most useful addition in this report.** It's MIT-licensed, runs from the CLI, and its agent red-team targets an HTTP endpoint on `localhost`. Its plugins map directly onto this harness's risks ([promptfoo docs](https://www.promptfoo.dev/docs/red-team/agents/)): `excessive-agency`, `tool-discovery`, `hijacking`, `bola`/`bfla`, `ssrf`, `mcp`, `agentic:memory-poisoning`, `cross-session-leak`, and a custom `policy`. A `policy` could encode a project rule such as "write tools act only on Experiment Sessions". OpenAI acquired promptfoo in March 2026, and the founders say the OSS suite continues ([TechCrunch](https://www.techcrunch.com/2026/03/09/openai-acquires-promptfoo-to-secure-its-ai-agents/)). Its long-term direction is the main open risk. Run it locally against an Experiment Session, with attack generation and grading routed through OpenRouter if it supports that (unconfirmed). garak and PyRIT test the model more than the tool layer and bring in a Python toolchain ([AppSecSanta](https://appsecsanta.com/ai-security-tools/llm-red-teaming)).

AI pentesters belong in the same "run it once, by hand" category. **Strix** (Apache-2.0) and **Shannon** (AGPL-3.0) are the serious self-run options. Both are Docker-sandboxed, take your own LLM key (OpenRouter supported), and report only findings with a working proof of concept ([Strix](https://github.com/usestrix/strix); [Shannon](https://github.com/KeygraphHQ/shannon)). A full Shannon run takes about 1–1.5 hours. Neither project publishes per-run LLM costs, and Shannon warns it can create users and change state. Both install with `curl | sh` or `npx ...@latest`, which breaks the exact-pin rule, so a run needs a pinned version and image digest and a throwaway target. The commercial services are out of range: XBOW's earlier tiers started at **$4,000 per test** before it dropped published pricing ([CodeAnt](https://codeant.ai/blogs/xbow-pricing)), and an Aikido standard pentest is **4,000 credits ($4,000)** ([Aikido help](https://help.aikido.dev/pentests/pentest-pricing)). Coverage-guided fuzzing is a poor fit too, because Jazzer.js shows no npm releases in 12 months ([Snyk Advisor](https://snyk.io/advisor/npm-package/@jazzer.js/fuzzer)).

## AI security reviewers are a second opinion and a new trust boundary

`docs/research/pr-review.md` already covers general AI PR review (Copilot code review with Pro, or the Claude Code GitHub Action otherwise). This section covers only the security-specific reviewers. The evidence says AI reviewers add to deterministic scanners and don't replace them. An academic study found Copilot code review often misses SQL injection, XSS and insecure deserialization ([PMLR 2026](https://proceedings.mlr.press/v318/amro26a.html)), and vendor claims of AI triage pushing false positives below 5% are unverified marketing ([Arnica](https://www.arnica.io/blog/ai-powered-sast-tools-false-positives)).

The cheapest deep option is **Claude Code's `/security-review` run locally** before a PR. It needs no CI secret, covers injection, authn/authz, data exposure, crypto and TOCTOU, and can be customised by copying `security-review.md` into `.claude/commands/` ([anthropics/claude-code-security-review](https://github.com/anthropics/claude-code-security-review)). The same repo ships an MIT GitHub Action that reviews diffs with a second false-positive pass. Its README says it "is not hardened against prompt injection", though, and the risk is documented. "Comment and Control" got the Claude Code Security Review Action, the Gemini CLI action and the Copilot agent to leak CI secrets ([CSA](https://labs.cloudsecurityalliance.org/research/csa-research-note-ai-coding-agent-ci-prompt-injection-202608/)). Microsoft found a hidden-comment path in the Claude Code GitHub Action that read `/proc/self/environ` (patched in v2.1.128) ([Microsoft Security](https://www.microsoft.com/en-us/security/blog/2026/06/05/securing-ci-cd-in-agentic-world-claude-code-github-action-case/)). As a solo repo with no outside contributors, forge-lab faces little fork-PR risk. Putting an API key into a CI that currently holds none still moves the security model, so keep `/security-review` local unless that trade is made on purpose.

**CodeRabbit** has no free private-repo tier. Essentials is **$24/user/month annual or $30 monthly, for 1 linked repo**. Its "Security Code Review" bundles third-party scanners such as Betterleaks and ESLint, and Deep Scan is priced separately ([CodeRabbit pricing](https://www.coderabbit.ai/pricing); [docs](https://docs.coderabbit.ai/tools/)). Data Retention caching and learnings embeddings are on by default ([Trust Center](https://coderabbit.ai/coderabbit-trust-center)). Its January 2025 RCE leaked a GitHub App key with access to about 1M repos ([Kudelski](https://kudelskisecurity.com/research/how-we-exploited-coderabbit-from-a-simple-pr-to-rce-and-write-access-on-1m-repositories)). For this repo it would duplicate gitleaks and Biome and cost $360/year. The frontier-lab whole-codebase scanners aren't available here: Anthropic's Claude Code Security is a Team/Enterprise preview ([IT Daily](https://itdaily.com/news/cloud/anthropic-launches-claude-code-security)), OpenAI's Codex Security uses ChatGPT/Codex allowances and may be Enterprise-only on connected repos ([eesel.ai](https://www.eesel.ai/blog/codex-security-cloud)), and Google's CodeMender is still research ([CSO Online](https://www.csoonline.com/article/4068774/google-deepmind-launches-an-ai-agent-to-fix-code-vulnerabilities-automatically.html)). Greptile, Cursor Bugbot and Graphite Diamond are general bug reviewers, with no security-specific evidence behind them ([cubic.dev](https://www.cubic.dev/blog/ai-code-review-pricing)).

**WorkOS has no code-security product.** Its own product index lists AuthKit, SSO, Directory Sync, RBAC, FGA, Audit Logs, Radar (auth-time fraud protection), Vault (encrypted data storage), Feature Flags and agent-auth features, and nothing that reviews or scans code ([WorkOS llms.txt](https://workos.com/llms.txt)). Its link to "securing the codebase" is indirect. **AuthKit is free up to 1M MAU**, and handing authentication and authorisation to it removes a class of bugs you'd otherwise have to review yourself. That matters only if Cartographer or the harness ever grows real users or binds beyond loopback.

## Recommended stack

The free baseline adds three things to what CI already runs, and the paid tier buys LLM tokens rather than seats.

| Tier | Tool | Where it runs | Cost | Status in forge-lab |
|---|---|---|---|---|
| Free baseline | gitleaks CLI (full history), pinned binary | CI `secrets` job + pre-commit | $0 | Done |
| Free baseline | zizmor + actionlint, pinned binaries | CI `workflows` job + pre-commit | $0 | Done |
| Free baseline | `bun audit`, Dependabot alerts and updates with 7-day cooldown, exact pins, `ignoreScripts` | CI `deps` job + repo settings | $0 | Done |
| Free baseline | **Semgrep Free Edition** (`semgrep ci`, Code + Supply Chain, cross-file, reachability) in its own job with the token scoped to it; Opengrep binary if no token is acceptable | New CI `sast` job | $0 | Add |
| Free baseline | **Socket free GitHub App** on forge-lab only; keep it only if it reads `bun.lock` | GitHub App, PR comments | $0 | Trial |
| Free baseline | **Claude Code `/security-review`** before opening security-relevant PRs | Locally, no CI secret | Existing subscription or tokens | Add to workflow |
| Free baseline | **promptfoo agent red-team** with a `policy` for Experiment-Session-only writes | Locally against loopback harness | LLM tokens only | Add as an Experiment |
| Paid upgrade | Capped LLM budget for promptfoo runs, a one-off pinned Strix or Shannon run, and optionally the `claude-code-security-review` Action on PRs | OpenRouter / Anthropic key the user enters | **~$10–20/month cap you set** (per-run costs unpublished) | Optional |
| Paid upgrade, only if the Security tab matters | Move the repo to a GitHub Team org + Code Security (CodeQL, Copilot Autofix, SARIF UI) ± Secret Protection | GitHub | **$34–53/month** for one committer | Not recommended now |

Skip these: SonarQube in any edition, Snyk (no `bun.lock`), DeepSource, Codacy, CodeRabbit ($30/month, 1 repo, duplicates current checks), ZeroPath, DryRun, XBOW, Aikido pentests, StackHawk, Burp, Escape, Nuclei, OSV-Scanner as a third CVE feed, Scorecard, poutine, Harden-Runner (not free on private repos), Jazzer.js and ClusterFuzzLite, Trivy and Grype on a Bun-only repo, and WorkOS until there are users to authenticate. Revisit ZAP's API scan, a paid pentest, and WorkOS AuthKit if the server binds beyond loopback, gets deployed, gains multi-user auth, or other people start using it.

## Open questions to verify

Several facts above came from summarised fetches or fresh releases and need a hands-on check before anything is wired in.

- **Semgrep and Bun.** Does Semgrep Supply Chain actually parse this repo's `bun.lock` with workspaces? v1.179.0 is three weeks old and the official docs don't list Bun yet.
- **What Semgrep uploads.** Its privacy page returned a 404, so what `semgrep ci` sends to Semgrep's servers is unconfirmed.
- **Semgrep PR comments.** Does Free post PR comments on private repos, or only fail the job?
- **Semgrep repo cap.** Sources disagree on 10 vs 50 private repos.
- **Socket and Bun.** Does Socket's GitHub App parse text `bun.lock`? Is the free tier 1 seat or 5 members?
- **Opengrep taint depth.** Does it do cross-file or only cross-function taint on TypeScript, and what is its current release?
- **promptfoo models.** Which model generates attacks and grades results by default, can both go through OpenRouter, and has the OSS cadence held since the OpenAI acquisition?
- **LLM cost per run.** Neither Strix nor Shannon publishes figures. Measure one run on `glm-5-3-flash` versus `opus-5-5` as an Experiment.
- **GHAS for one person.** Are the $19/$30 per-committer prices current? GitHub's October 2026 pricing page didn't show them. Is GitHub's native "require SHA pinning" setting available to personal-account repos on Free?
- **Betterleaks.** Who governs gitleaks after March 2026, and does Betterleaks hold up independently of its own recall benchmark?
- **Pilot before committing.** A pilot on a seeded file of known TypeScript vulnerabilities (taint into `Bun.spawn`, an authz skip, a prompt-injected tool output) would show which of Semgrep, Opengrep, Corgea Free and `/security-review` actually catch them. No published benchmark answers that for TS/Bun.

## Conclusion

The question changes once you look at this repo. forge-lab doesn't need a SonarQube replacement so much as the two layers SonarQube never offered: data-flow SAST with dependency reachability (Semgrep Free), and adversarial testing of the agent itself (promptfoo). The second matters more, because no static scanner models "a tool output convinced the agent to write to a user's chat Session". GitHub Free's paywall turns out to be a design pressure more than a loss: it pushes every tool toward pinned binaries that fail a CI job, which is also the pattern that survived the Trivy and tj-actions compromises.

The other implication is about trust boundaries. Each upgrade on offer (a SaaS reviewer's GitHub App, an LLM key in CI, a pentester that mutates its target) adds a new credential holder or attack path to a CI that currently holds no secrets. Adopt each one deliberately, record it in `docs/research/security-review.md` as a boundary change, and prefer the local, no-secret version of a tool whenever one exists.
